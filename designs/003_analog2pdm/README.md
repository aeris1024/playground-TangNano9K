# 003_analog2pdm

PCM1808基板2枚のステレオ音声を、それぞれ独立したPDMクロックに従う
ステレオPDM 2ポート、合計4チャンネルへ変換します。

**実装・シミュレーション・数値検証・配置配線まで確認済みです。
ADCとMCHStreamerは未配線のため、実機への書き込み・録音確認は行っていません。**

配線と実機確認は[配線・測定手順](../../docs/analog2pdm_wiring.md)を参照してください。

## 信号処理

系統A/BはPLL、FIRの演算器、履歴メモリー、FIFO、ΔΣ変調器をそれぞれ持ちます。
A/B間で音声データを受け渡しません。系統内の2チャンネルで各FIR段の乗算器を共用します。

```text
独立した3.072 MHz入力 → rPLL ×4 → 12.288 MHz ADC MCLK
                                 ├ ÷4   → ADC BCLK
                                 └ ÷256 → ADC LRCLK
ADC DOUT → 24 bit I2S受信 → 1/2利得 → FIR ×2 ×2 ×2 → 8語ステレオFIFO
                                              ↓ 相手の元のPDMクロックへ渡す
                                      CIC ×8 → 2次ΔΣ(L/R) → ODDRC → PDM DATA
```

FIFOは同一系統内のPLL出力と元のPDMクロックの位相差を吸収します。
384 kHzのステレオ語を渡すので、FIFOの読み出し側で8倍補間して3.072 MHzとします。
2語以上溜まってから開始し、アンダーフローは異常LEDに記録します。

- FIR: 95/31/15タップ、Kaiser β=8.6、係数18 bitのQ2.16、積和50 bit。
- 段間: 24 bitへ最近傍丸め（ちょうど半分はゼロから遠い方向）と飽和処理。
- CIC: 3次・8倍、36 bitの剰余演算、利得64を補正。
- ΔΣ: 2次誤差帰還。4chそれぞれ独立した状態を持ちます。
- 1/2利得は−6.0206 dBです。入力−6 dBFSの評価音は、出力では約−12.02 dBFSになります。

## クロックと状態

公称3.072 MHz専用です。MCHStreamerは48 kHzに設定してください。
2.8224 MHz（44.1 kHz系）は監視回路が無効な周波数として判定し、その系統をミュートします。
各系統は、周波数判定、PLL LOCK、同期リセット解除、250 ms待ち後に処理を開始します。
クロック停止時はその系統だけをリセットし、PDM出力をLowにします。
クロックが動いているミュート中は、L/R各チャンネルに50%密度の無音パターンを出します。

`top.sv`の`SWAP_EDGES_A/B`は既定値0です。
MCHStreamer向けにLは立ち下がり、Rは立ち上がりで取り込みます。
1に変更して再ビルドすると、そのポートのL/R割り当てが入れ替わります。
ODDRCの機能モデルは、ベンダーモデルと同じパイプライン遅延を持たせています。

| LED | 表示 |
|---|---|
| 1 / 4 | A / BのPLL LOCK |
| 2 / 5 | A / BのPDM処理開始 |
| 3 / 6 | A / Bの飽和、FIFOオーバーフロー／アンダーフローなどの異常 |

異常はその系統のリセットまで保持します。クロックの停止・復帰でリセットできます。

## ソフトウェア検証

```powershell
python -m unittest discover -s tests -v
python designs\003_analog2pdm\model\generate_coefficients.py --check
.\fpga.ps1 doctor
.\fpga.ps1 sim 003_analog2pdm
python designs\003_analog2pdm\model\verify_audio.py --rtl
.\fpga.ps1 build 003_analog2pdm
```

音質の数値検証と係数生成にはNumPyが必要です。CLI自体の依存は引き続きPython標準ライブラリのみです。
`generate_coefficients.py`の`--check`なしの実行は管理対象の係数を再生成します。

`sim`はPCM1808モデル2枚を使い、符号とI2Sの1 bit遅延、PDM密度、左右分離、
エッジ交換、±1000 ppm、片系停止・復帰、2.8224 MHz時のミュートを自己判定します。
250 msの起動待ちだけ短縮して実行します。

`verify_audio.py --rtl`は、次を検証して`build/003_analog2pdm/audio/`へ結果を保存します。

- 3段のFIRとCIC・ΔΣを、ランダム値と境界値でRTL／Pythonモデル間のビット単位比較。
- I2Sの192ステレオフレームについて、左右すべてのデータビットを比較。
- 量子化済み係数による20 Hz〜20 kHzの解析応答。
- 固定小数点モデルから生成したPDMの20 Hz、1 kHz、20 kHzにおける振幅。
- 各chについて1 kHz・入力−6 dBFSのTHD+N。20 Hz〜20 kHz、非重み付け、DC除外。
- 無音、正負フルスケール、フルスケールステップ、インパルスの状態安定性。

CLIは配置配線後のsetup/hold違反数も確認し、違反があればビットストリームの正規化を行わず失敗します。
SDCの非同期FIFO例外はGrayポインターの第1同期段だけです。
音声経路、FIFOデータ、同期段以降はタイミング解析の対象に残します。

## 確認できた結果と残る確認

- 数値モデル: 振幅偏差−0.1127〜+0.0007 dB、4chのTHD+Nは−70.15〜−69.70 dB。
- 量子化・符号・I2Sのビット比較、全体シミュレーションはPASS。
- 配置配線は2/2 PLLを使用し、setup/hold違反0件で完了。
- DSPブロック10/10、BSRAM12/26を使用するため、DSPには追加機能用の余裕がありません。
- ピン63と49からPDMクロックを内部へ配る区間にはGowinのPR1014（一般配線を使用）の警告が残ります。
  静的解析のsetup/holdは通っていますが、配線後の波形と受信結果は実機で確認します。
- SDCのPDM出力は、外部側のsetup予算20 ns・hold予算0 nsで解析しています。
  MCHStreamerの実機配線を含む仕様保証値ではなく、初期検証用のI/O予算です。
- ADCのBCK→DOUT遅延にはデータシートの−10〜40 nsと配線余裕を考慮し、−10〜50 nsを設定しています。
  ADCのMCLK/BCLK/LRCLKの波形・相対スキューは配線後に測定してください。
- MCHStreamer 1台のCLKとCLK2は複製なので、非同期動作の実機証明にはなりません。

実機の4ch録音が確認できるまで、FlashのLチカは置き換えません。

AのCLKはJ6-1（FPGAピン63）、BのCLKはJ6-19（ピン49）です。
