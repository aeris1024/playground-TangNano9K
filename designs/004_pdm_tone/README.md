# 004_pdm_tone

ADCとI2S受信を迂回し、48 kHzの内部PCMを既存のFIR・CIC・2次ΔΣ・DDR出力へ通す診断です。
003のRTLを独立した診断スナップショットとしてコピーし、i2s_receiveだけをテスト音源へ置き換えています。
003のRTLやbitstreamは変更しません。ADC DATA端子は参照しません。

## 使い方

MCHStreamerをPDMファームウェア、48 kHzで動作させます。外部PDMクロックは引き続き必要です。
ADCやPCの音楽再生は不要ですが、ADC用のクロック出力は従来どおり出ます。

USB-Cを上にした部品面から見て右側のJ6:

| 信号 | FPGAピン | ヘッダー |
|---|---:|---|
| CLK A | 63 | J6-1 |
| DATA B | 48 | J6-19 |
| CLK B | 49 | J6-20 |
| DATA A | 31 | J6-21 |
| GND | — | J6-23 |

J6-18は5 V電源です。信号を接続しないでください。
LEDは003と同じで、1/2がAのLOCK/処理開始、4/5がBのLOCK/処理開始、3/6が異常です。

## 出力する音

各系統はPLL起動待ち250 ms後、無音0.5秒から開始します。
100 Hz → 1 kHz → 5 kHz → 10 kHz → 15 kHz → 20 kHzを各3秒、間に無音0.5秒で繰り返します。
両系統・左右は同じ音ですが、クロックが独立しているため切り替わり時刻は完全には一致しません。
音源ピークは−18 dBFS、003と同じ1/2利得を入れたPCMピークは−24.0206 dBFSです。
理想的な復調後の正弦波RMSは約−27.03 dBFSです。受信側の利得等で絶対値は変わるため1 kHzとの差で評価します。
周波数切り替え・無音からの立ち上がりには過渡応答が出るので、各区間の中央でRMSを読んでください。
FIR+CICの理論上の相対減衰は5k:−0.006、10k:−0.027、15k:−0.063、20k:−0.113 dBです。

内部音でも大きく高域が落ちる場合は、FPGA処理・クロック・MCHStreamer・モニター側を調べます。
内部音が平坦で003だけ減衰する場合は、PCのアナログ出力・ADC基板・配線・I2S受信を調べます。
内部音が正常でもI2S受信まで検証できたことにはなりません。

## 検証

```powershell
.\fpga.ps1 doctor
.\fpga.ps1 sim 004_pdm_tone
.\fpga.ps1 build 004_pdm_tone
.\fpga.ps1 program 004_pdm_tone
```

自己判定テストは6周波数のPCM値を正弦波の数値計算と比較し、無音区間も検証します。
全体回路では異なるクロック位相・±1000 ppmの片系クロックで1 kHz PDMの基本波振幅を確認します。
起動待ち・無音待ちは短縮し、内部音の開始周波数だけ1 kHzへ変更して検証します。

| 周波数 | RMS dBFS | 1 kHz基準 dB |

内部音では、ADC経路の測定で生じた数十dBの高域減衰は再現しませんでした。
大きな減衰の調査対象はPC再生・アナログ出力・配線・PCM1808基板・I2S受信です。
内部音はI2S受信も迂回するので、ADC基板だけを原因と断定しません。
20 kHzには1 kHz比−3.4 dBの低下が残っています。FPGA単体の理論値と同一視せず、
PDM配線・受信側フィルタ・モニターの測定処理等も含む未解決項目として残します。
測定チャンネルは未指定です。
